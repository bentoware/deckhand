# deckhand fix

Repair weak cards, leeches, missed cards, and cards the learner keeps struggling with. Start from the learner's pain and improve the card enough to help future reviews; repeated failure is card-design feedback, not learner failure.

## Intent-first recipe

- Find the painful cards from whatever clue the user gives: named cards, Browser selection, deck/tag, "the ones I missed", leeches, high-lapse cards, or findings from `check`.
- Diagnose enough to choose a better card design. Use the actual note, rendered card if helpful, review stats, sibling cards, and [../references/rubric.md](../references/rubric.md). Do not turn diagnosis into busywork when the fix is obvious.
- Propose the smallest useful repair: split, add context, clarify the prompt, add a contrast, change direction, narrow a cloze, add a citation, add a hook, suspend/tag low-value material, or ask for source material when truth is missing.
- Show exact before/after field text for edits. Apply only on approval; back up first when touching more than a handful of notes.

## Scheduling honesty

Fixing a card's text doesn't fix its review history. Offer, but never silently do, scheduling changes (forget/reposition, unsuspend, due-date moves) — and explain the consequence in one plain sentence before the user decides.
